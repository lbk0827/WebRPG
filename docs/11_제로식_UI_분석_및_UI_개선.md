# 제로식 웹사이트 UI 분석 → 우리 UI 개선 (ADR-004)

- **조사일**: 2026-09-10. 대상: `hof.zerosic.com` 공개 화면 (메인 · 전투로그 · 게임데이터 · 매뉴얼 · 튜토리얼 · 신규).
  로그인 뒤 화면은 계정을 만들지 않았으므로 **매뉴얼·튜토리얼의 설명으로만** 파악했다.
- **클린룸**: 여기 적은 것은 화면 **구성과 정보 구조의 관찰**이다. 텍스트·이미지·CSS 는 가져오지 않는다 ([00 정책](00_클린룸_정책.md)).
- **결정**: §4 의 개선안을 M2-2 앞에 먼저 구현한다 (단장 결정 — "UI 부터 개선하고 가자").

## 1. 제로식 사이트 구성 (관찰)

### 1.1 골격
| 항목 | 관찰 |
|---|---|
| 레이아웃 | **가로 810px 고정** 프레임을 가운데 정렬. `min-width` 도 810 — 폰에서는 축소되어 글씨가 읽히지 않는다 |
| 모바일 | `viewport` 메타 없음. 터치 대응 없음. 2007년 PC 웹 그대로 |
| 서체·색 | 굴림 14px. 회청색 바탕 위에 짙은 남색 본문 상자, 글자는 연한 회청색. 로그에서만 12색 넘게 사용 |
| 상단 메뉴 | Top · 신규 · 규칙과 메뉴얼 · 게임의 데이터 · 전투로그 · 게시판(네이버 카페 — 외부) |
| 하단 | UpDate · Manual · Tutorial · GameData · Top, 접속자 수, 저작권 |
| 기술 | PHP + prototype.js, 채팅 스크립트, reCAPTCHA. 페이지 이동식(SPA 아님) |

### 1.2 메인(로그인 전)
1. 로그인 상자 (ID/PASS, NewGame 링크)
2. **랭킹 상위 5** — 팀명과 전적 `(N전 N승 N패 N무 N방 승률 N%)`
3. **3문답 소개** — "이건 무슨 게임?" / "전투는 어떤 느낌?" / "관련정보?" 각각 두세 줄
4. info — 가입자 수 / 상한, 182일 미접속 삭제 안내

→ 첫 화면이 곧 **"이 게임의 목적은 랭킹 1위"** 선언이다. 게임 소개가 세 문답으로 끝나는 밀도는 배울 만하다.

### 1.3 로그인 후 메뉴 (매뉴얼 기준)
`Top(캐릭터 일람) · 전투(Hunt) · 아이템 · 가게(알바 포함) · 랭크 · 고용 · 설정 · 로그` + 하단에 `팀명 · 자금 · 시간`.
튜토리얼에는 `마을(Town) → 인재알선소`, `사냥(Hunt) → 고블린과 놀기` 같은 2단 메뉴가 보인다.

### 1.4 캐릭터 화면 (스테이터스)
- 스탯 8항목(Exp/MaxHP/MaxSP/Str/Int/Dex/Spd/Luk) — 스탯 이름에 **마우스를 올리면 설명**이 뜬다 (튜토리얼 언급)
- 장비 슬롯 + 착용 가능 종류 + `handle` 상한
- 기술 목록: `이름 / 대상-선택 / 소비SP / 위력%×횟수 / 속성 / (준비:대기) / 비고` 한 줄 포맷
- **패턴 표**: `No | 판정(select) | 사용 기술(select)` 행 반복. 판정은 **프리셋 문장 100여 개**를 고르는 드롭다운
- 배치(전방/후방) + 후위 지키기(엄호) 조건 select

### 1.5 전투 로그
- 목록: All / Common / Adventure / Boss / Union / Ranking 탭. 한 줄에 `시각 · 턴 수 · A(인원:평균Lv) vs B · [DAM:총피해]`. 비공개 로그는 `??/??` 로 가려짐
- 상세: 헤더(양 팀 레벨 합·평균·총 HP) → 캐릭터 카드(Job/HP/SP/TP 게이지) → 행동 블록 `- 이름 / Skill: X / 결과 줄들…` → 전투 후 대사
- 200턴 전투 하나가 **세로 13,000px** 짜리 텍스트. 시각화·요약·검색 없음. "왜 졌는가"는 독자가 직접 읽어서 찾는다
- `로그 주소 복사` 버튼 — 공유 URL

### 1.6 게임데이터 · 매뉴얼 · 튜토리얼
- 게임데이터: 직업(9계열 × 최대 3단, 40여 종 — 각 직업의 장비 목록과 기술 표) / 아이템 / **판정(조건 전체 목록)**. 한 페이지에 전부 나열
- 매뉴얼: 한 페이지 앵커 목차 17항목. 개발자의 자조 섞인 톤("설명이 매우 어렵습니다", "미칠듯이 귀찮은 게임"). "고수용 메뉴얼" 별도
- 튜토리얼: **NPC(오필리아) 의 단계별 퀘스트 대사**로 파티 → 스탯 → 장비 → 스킬과 패턴 → 제작 → 모험을 가르친다. 게임 안 퀘스트로도 제공

## 4. 우리 UI 개선안 (이번에 구현)

### 4.1 화면 구조
```
헤더  [교전 수칙]  용병단 이름 · 금 · 단원 N · 평균 Lv · N전 N승        [도감]
탭    본부 · 의뢰 · 단원 · 수칙 · 훈련장        (폰: 하단 고정 / PC: 헤더)
```
| 탭 | 내용 |
|---|---|
| **본부** (새로 만듦, 시작 화면) | 처음이면 3문답 소개 → 할 일 목록 → 훈련 과제 진행(N/12, 다음 과제 열기) → 최근 전투 기록(재생) |
| 의뢰 | 지역 선택 → **출전 전 비교 카드** → 출전 → 결과(보상·레벨업·**진단**) → 재생. 기록에 자동 저장 |
| 단원 | 편성 + 단원 카드. 스탯 **툴팁·설명**, 카드에서 **수칙 편집으로 바로 이동**, 용병단 **이름 바꾸기**, 저장 관리 |
| 수칙 | 스킬 선택 아래 **스킬 한 줄 요약** (SP · 대상 · 준비/경직 · 효과), 선택지에 SP 표기 |
| 훈련장 | 그대로 |
| 도감 (헤더 버튼) | 스킬 · 상태이상 · 특성 · 조건 종류 · 스탯 · 지역/상대 |

훈련 과제 목록은 본부 안으로 들어간다 (탭 5개 유지 — 폰 하단 바 한계).

### 4.2 저장 스키마 v2
```
GameSave { version: 2, name, gold, members, party, regionWins, battles, wins, log: BattleRecord[≤12] }
BattleRecord { at, regionId, seed, outcome, exp, gold, actions, player: TeamSetup, enemy: TeamSetup }
```
v1 저장은 자동 승격 (이름 기본값, wins 는 regionWins 합, log 빈 배열). 기록은 **양 팀 편성 전체**를 저장한다 —
그래야 나중에 단원이 성장해도 그때 그 전투를 정확히 재생한다 (결정론).

### 4.3 하지 않는 것
- 랭킹 · 채팅 · 게시판 — M3 (서버) 이후
- 다크 모드 — 요청 있을 때
- 로그 공유 URL — 서버 없이는 시드+편성을 URL 에 넣어야 해서 너무 길다. 내보내기 JSON 으로 대신

## 5. 로그인 후 화면 관찰 (2026-09-10, 단장 계정으로 열람 — 읽기만)

§1 은 공개 화면이었다. 단장이 로그인한 Chrome 을 통해 실제 플레이 화면을 읽었다. 버튼은 누르지 않았다.

### 5.1 화면 구성
| 화면 | 구성 |
|---|---|
| **Top** | 메뉴 10개(Top·자경단·전투·모험·시나리오·아이템·마을·설정·로그·BBS·CHAT). 상태줄 `팀명 · Funds · Time · Work · Auction`. 본문은 검은 바탕 위 캐릭터 스프라이트 하나 + `Lv.2 Warrior`. 할 일 안내 없음 |
| **캐릭터** (한 페이지, 세로 6절) | ① 스탯 8 + 파생 수치(명중률 보정·완전 방어·닷지) + 정체불명 버튼 4개(Use·기도한다·Kick·Knockback) ② 스탯 분배: 스탯별 `+0~+5` 셀렉트 → Increase ③ **상태 저장 3슬롯**(패턴+위치+호위를 이름 붙여 저장) ④ **Action Pattern**: 행 = `[조건 셀렉트] [숫자] [스킬 셀렉트]`, 버튼 Set Pattern · **Set & Test** · Simulate · Switch · Add · Delete ⑤ Position & Guarding (라디오 + 셀렉트 + Set) ⑥ Equipment: 슬롯 12 라디오, Remove · Equip Load(1)/Save(1)/Load(2), handle 3/6 · cost 0/10 두 제약, Stock 카테고리 셀렉트 17개 ⑦ Skill: 개성 · Mastered · 신앙 · 공용 · 패시브 · Learn New(라디오 + pt 비용 + Learn) |
| 조건 셀렉트 | **옵션 약 250개** 한 드롭다운. 그룹 제목("HP", "SP(적)", "독(적)"…)이 선택 가능한 옵션으로 섞여 있음. `○○` 자리에 옆 숫자칸 값이 들어감. "다음 턴으로 넘긴다"(행 건너뜀), "○○회까지 반드시", "○○%의 확률로", think over 전용 조건 등 |
| **전투** | 지역 7개 접이식(적정 레벨, 하위 맵 수) — "클릭 안되면 F5" 안내. 하위 맵: **파티 저장 3슬롯**, 캐릭터 체크박스, `싸우자!` · **`3번 싸우자!`** 버튼이 위아래 두 벌, Map Information(그림+설명), MonsterAppearance(이름+Lv) |
| 모험 · 시나리오 | 일간/주간 챌린지 리셋 알림, 순환 퀘스트, 레이드. 각각 최근 로그 15줄 |
| 아이템 | 카테고리 셀렉트 하나뿐인 빈 화면 (아이템이 없어서) |
| **마을** | 링크 **35개** 세로 목록 (연금 학회 · 검문소 · 콜로세움 · 가게 5 · 조합(퀘스트·인재) · 대장간 4 · 상점가 5 · 카드 5 · 에코 · 레이드 정보 · 신전 · 신문 · 옥션) + 멍에의 전당(제련 성공 로그) + 마을 BBS(거래 채팅) |
| 인재 알선소 | 직업 9종 그림 + 가격 그리드, 이름·성별 입력, 최대 99명 |
| 모험 알선소 | 퀘스트 표 `이름 / 타입 / 제한 / 보상 / 수락` + 진척 `[0/8]` + NPC 대사 |
| 가게 | 산다/판다/아르바이트 탭. 아이템 표 `체크 · 가격 · 수 · 스펙 한 줄` |
| 자경단 | **매크로 방지 캡차**. 통과하면 Time 보상 |
| 설정 | 로그 공개, JS 끄기, 채팅, 단축키, BGM, 타운맵/모바일 타운맵, 색상 팔레트 200여 개, 팀명 변경 $10,000,000, 계정 삭제 |
