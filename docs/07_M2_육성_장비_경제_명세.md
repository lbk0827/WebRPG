# M2 명세 — 육성 · 장비 · 경제 (Draft v0.1)

- **결정**: 투기장(PvP)보다 육성·장비·경제를 먼저 만든다 (2026-09-10, 단장 결정)

---

## 0. 왜 PvP 보다 먼저인가

1. **인구가 없다.** 비동기 PvP 는 "저장된 남의 편성"과 싸우는 것인데 지금 플레이어는 한 명이다
2. **인프라가 다르다.** PvP 는 계정·서버가 필요하다. 육성·장비·경제는 **서버 없이 로컬만으로** 완성되며, 현재의 GitHub Pages 배포 그대로 굴러간다
3. **목적이 필요하다.** 지금은 "과제 12개 풀면 끝"이다. 의뢰 → 보상 → 성장 → 더 어려운 의뢰 루프가 게임을 게임으로 만든다

→ **M2 = 서버 없는 싱글 육성 루프.** 계정·서버·PvP·거래소·행동력은 M3 로.

## 1. M2 의 질문

> **"수칙을 짜는 재미가 성장과 결합되었을 때 더 커지는가, 아니면 레벨이 수칙을 대체해 버리는가?"**

이것이 M2 가 검증할 유일한 것이다. 육성 게임의 고질병은 "수칙이고 뭐고 레벨 높은 쪽이 이긴다"이고,
그 순간 이 게임의 정체성은 사라진다.

### 설계 제약 (측정 가능하게)

> **"같은 레벨에서 좋은 수칙 vs 나쁜 수칙의 승률 차이" > "레벨 5 차이의 승률 차이"**

훈련장 배치로 주기적으로 측정한다. 이 부등식이 깨지면 성장 수치를 낮춘다. 제곱근 스케일링(§4.3)이 1차 방어선이다.

## 2. 코어 루프

```
[의뢰소] 지역 선택 (권장 레벨 표시)
   ↓
[출전] 5명 편성 + 수칙 → 자동 전투 (M1 엔진 그대로)
   ↓
[보상] 경험치 · 금 · 재료 · (드물게) 장비
   ↓
[성장] 레벨업 → 스탯/스킬 포인트 분배, 스킬 습득, 전직, 패턴 슬롯 확장
[장비] 공방에서 제작·강화, 상점에서 구매
   ↓
[다음 의뢰] 더 어려운 지역 → 처음으로
```

훈련 과제(M1)는 **튜토리얼**로 남는다. 자유 훈련은 **훈련장**(행동력 없이 반복 대전)으로 남는다.

## 3. 시스템별 결정

각 항목은 [01 시스템 명세서](01_시스템_명세서_초안.md) 의 관찰(S번호)을 기반으로 **우리의 결정**을 적는다.

### 3.0 전투 기반 보강 — M2-0 (단장 지적, 2026-09-10: "기본 전투가 완벽히 갖춰진 것 같지 않다")

M1 엔진은 뼈대(게이지·엄호·시전·결정론·조건/효과)는 단단하지만 **육성이 매달릴 고리가 없다.**
육성을 얹기 전에 엔진 레벨에서 채운다. 전부 테스트로 검증 가능.

| 항목 | 현재 | 보강 |
|---|---|---|
| 데미지 공식의 장비 항 | 스탯만 참조 | `atkBonus(물/마)`, `defBonus(비율/고정 × 물/마)` 항 추가. 장비·특성이 여기에 합산 |
| 특성(trait) 시스템 | 없음 | **패시브 스킬과 장비 특성이 공용으로 쓰는 장치.** 예: 시전 시간 −20%, 엄호 피해 −15%, 후열 대상 피해 +10%, 시작 게이지 +200, 지속 회복. 데이터로 정의, 엔진은 훅 지점만 제공 |
| 스탯 체계 | STR·INT·SPD (+HP·SP·DEF·MDEF) | ✅ **5종 확정 (2026-09-10, 단장 결정)**: STR · INT · **DEX** · SPD · **LUK**. DEX = 도적·궁수 계열 물리 스킬의 위력 스탯(`scaleBy: 'dex'`) + 선딜 단축(⌊DEX/4⌋%, 최대 25%). LUK = **상태이상 저항** — 적의 디버프를 `(내 LUK − 상대 LUK)/4`%(0~30%) 확률로 저항. 시드 난수 위에서 굴러가므로 결정론 유지. 전투 밖에서는 드롭·제작 특성 확률(M2-4). **데미지 난수·치명타는 여전히 없다** |
| 상태이상 | 9종 | 최대HP/SP 증감, 지속 회복(재생), 도발? 추가 검토 |
| 능력치 비교 조건 | M1 제외 | `selfStat` 계열 부활 — 스탯이 변하기 시작하면 의미 생김 |
| 몬스터 전용 훅 | 없음 | 경험치·금·드롭 테이블 보유 (`monster` 플래그) |
| 명중/회피/치명타 | 없음 | **넣지 않는다.** 결정론 유지. 난수는 명시적 효과로만 |
| 소환·마법진·넉백 | 없음 | M3 |
| **효과 프리미티브 확장** | 8종 | [08 §1.4c](08_참고_제로식_유니콘오버로드.md) 에서 추린 확장 후보 — **`moveRow`(열 이동)** · 열 조건부 위력 · `falloff`(연타 점감) · `stiff` 음수(고속 행동) · `requires.weaponType` · `cooldown` / `perBattle` · `damageSp` / `drain` · `costHpPct`. 전부 데이터로 정의 가능해야 하며 하드코딩 금지 원칙 유지 |

> **진형을 동적으로.** 제로식 15년의 스킬 확장에서 가장 많이 늘어난 것이 "열을 바꾸는" 효과였다.
> 2열 진형은 고정이면 얕고, 전투 중에 바뀌면 전술 축이 된다. 수칙 조건 `selfRow` · `teamRowCount` 는 이미 있다.

> M2-0 은 화면이 바뀌지 않는 작업이다. 배포해도 플레이어에게 보이는 건 없다.
> 그래서 미루기 쉬운데, **나중에 뜯는 비용이 훨씬 크다.** M2-1 보다 먼저 한다.

**✅ M2-0 구현 (2026-09-10, 테스트 98개 통과, 과제 12개 회귀 없음)**

| 구현 | 위치 | 비고 |
|---|---|---|
| 장비 항 `CharSetup.bonus` — atk[물/마], def[물%·물고정·마%·마고정] | `damage.ts` | M2-4 장비가 채운다. 회복·SP 피해도 마법 가산 참조 |
| 특성 시스템 `CharSetup.traits` + `data/traits.ts` 8종 | `state.ts` `effects.ts` | 수동형(시전 단축·엄호 피해·후열 대상·시작 게이지·패턴 +1·저항) + **트리거형**(턴 시작·피격·저HP, 전투당 횟수) — UO 의 PP 구조 |
| `moveRow` (자신/대상, 전열/후열/교대) + `rowChange` 이벤트 | `effects.ts` | **열이 전투 중에 바뀐다.** 조건 `selfRow`·`teamRowCount`, 엄호, 스테이지 배치가 전부 현재 열을 본다 |
| 열 조건부 위력 `damage.rowBonus` | `damage.ts` | "내가 후열이면 3배" 류 |
| 연타 점감 `damage.falloff` | `damage.ts` | 2타부터 −N%p/타, 하한 10% |
| 후딜 음수 = 고속 행동 | `battle.ts` | 즉시 재행동은 900 으로 캡 |
| `cooldown` / `perBattle` / `requires.weaponType` / `costHpPct` | `battle.ts` | 실패 사유 `cooldown` `noWeapon` 추가 — 보고서에 "재사용 대기 / 무기 불일치" |
| `damageSp` / `drain`(직전 피해의 %를 HP·SP 로) | `effects.ts` | 마법사 상대 카운터 축 |
| 게이지 지연 누적 상한 1500 | `effects.ts` | 제로식 딜밀기 붕괴 대응. 초과분은 delta 0 으로 기록 |
| 조건 `selfStat` (힘·지능·손재주·속도·운 비교) | `conditions.ts` 편집기 | 스탯이 변하기 시작하면 의미 |
| 몬스터 훅 `CharSetup.monster` (exp·gold·drops) | `types.ts` | M2-1 에서 사용 |

미구현(M2 후속): 상태이상 확장(최대HP/SP 증감), 특성의 편집기 노출(M2-2 스킬트리와 함께), 장비 데이터(M2-4)

**참고 게임에서 가져온 것** ([08 참고 분석](08_참고_제로식_유니콘오버로드.md) §3.1)
- 특성/패시브는 **트리거(피격·공격·턴 시작·사망) + 전투당 횟수 상한**을 가진다 — 유니콘 오버로드의 PP 구조
- 게이지 지연 효과는 **같은 대상에 대한 누적 상한**을 둔다 — 제로식 "딜밀기" 붕괴 사례
- 패턴 슬롯은 **INT 로 결정** (✅ 구현) — 제로식 "패턴 수 = INT" 채택. 스탯 분배에 "수칙 공간"이라는 선택지가 생긴다
- 제작 특성 뽑기에 **천장** — 제로식 소울 에코(300개 확정)
- 훈련장 상대에 "시전 허수아비(끊기 연습)" "보스형" 추가 — 제로식 허수아비 16종
- 2차 직업 중 1~2개는 **파티당 1명** — 제로식 영웅직
- **규칙 언어의 기능을 성장 보상으로 해금** — 제로식 "think over"(AND 를 배워야 씀).
  후보: 레벨 1 은 단일 조건만 → 레벨 5 에 "N회만" → 레벨 10 에 AND → 레벨 15 에 OR/NOT.
  훈련 과제는 이미 이 순서로 가르치고 있다(과제 6 → M2 복합 조건). **M2-2 에서 결정**
- 장비 특성 후보에 **"패턴 +1"** — 제로식 Power Sphere. 초보 배려를 장비로 푸는 장치
- 조건값 입력에 **프리셋 칩(10/30/50/70/90%) + 직접 입력** 병행 — 제로식은 프리셋만. 폰에서 프리셋이 빠르다
- 소모품을 수칙의 **행동**으로 (예: "내 SP 20% 이하 → 물약") — 제로식 "아이템을 사용한다". M2-4 상점과 연결

### 3.1 저장 (신규)

- **서버 없음.** localStorage 에 저장. JSON **내보내기/가져오기** 제공 (기기 이동·백업·버그 리포트용)
- 저장 스키마에 `version` 을 두고 마이그레이션 함수를 처음부터 만든다 — M3 서버 이관 시 그대로 쓴다
- 결정론 엔진이므로 전투 결과는 저장하지 않고 **입력(시드·편성·수칙)만** 저장하면 재현된다

### 3.2 단원 획득 — 모집소 (S2)

- 직업 5종 중 골라 **금으로 고용**. 초기 단원 2~3명 무료 지급
- 최대 보유 **8명** (원본 10), 편성 5명. 안 쓰는 단원은 대기
- 고용 시 스탯은 직업 기본값 + 소폭 무작위(±5%) — "같은 전사가 둘"이 되지 않게. 이름은 플레이어가 짓는다
- 해고 = 삭제 (금 일부 환급). 단원 간 이동 없음

### 3.2b 스탯 정의 (확정, 2026-09-10 — 단장 제안을 우리 문장으로)

| 항목 | 정의 | 엔진 반영 |
|---|---|---|
| **Exp** | 다음 레벨까지 쌓아야 하는 경험치 | M2-1 |
| **MaxHP** | 체력 상한. 0 이 되면 전투에서 쓰러진다 | ✅ |
| **MaxSP** | 기술을 쓸 때 소모하는 자원의 상한 | ✅ |
| **STR** 힘 | 물리 공격의 위력 | ✅ 물리 기본치 = √STR 기반 |
| **INT** 지능 | 마법의 위력, SP 상한, **쓸 수 있는 최대 패턴 수** | ✅ 위력·**패턴 수 = 4 + INT 구간(10/20/35/50/70)마다 +1**. SP 상한 연동은 M2-1 |
| **DEX** 손재주 | 궁수·도적 계열 공격의 위력. (부가) 시전 준비 시간 단축 | ✅ `scaleBy: 'dex'`, 선딜 −⌊DEX/4⌋% (최대 25%) |
| **SPD** 속도 | 행동 순서가 빨리 돌아온다 | ✅ 게이지 충전 = √SPD 기반 |
| **LUK** 운 | 상태이상 저항. **소환수가 생기면 소환수 강화 (M3)**. 전투 밖에서 드롭·제작 확률 (M2) | ✅ 저항 / M3 소환 / M2 드롭 |

> 원본·제로식 매뉴얼의 정의를 참고했으나 **문장은 우리가 새로 썼다** (매뉴얼 텍스트는 어문저작물). 내용상 차이:
> STR 이 HP 에 영향하지 않음(HP 는 독립 스탯), DEX 에 선딜 단축 부가, LUK 에 저항 역할 추가.

### 3.3 성장 (S2 · S3 · S4)

| 항목 | 결정 | 근거 |
|---|---|---|
| 레벨 | 1 ~ **30** (M2 상한) | 원본 50은 후반 하드코딩 장벽이 있었다. 단일 연속 곡선으로 30까지 |
| 필요 경험치 | `base × level^1.6` 단일식 | 급증 구간 없음. 수치는 훈련장으로 튜닝 |
| 레벨업 보상 | 스탯 포인트 **5**, 스킬 포인트 **2** | 원본 관찰값. "강해지는 축"과 "할 수 있는 일" 분리 유지 |
| 스탯 상한 | 개별 **150** (M2) | 빌드 다양성 강제. 원본 250 은 레벨 50 기준 |
| 스탯 분배 | 전부 수동 + **"자동 분배(직업 추천)" 버튼** | 원본은 수동만. 초보 이탈 방지용 추천을 두되 기본은 수동 |
| 패턴 슬롯 | **INT 로 결정** — 기본 4 + INT 10/20/35/50/70 마다 +1 (✅ 구현, `progression.ts`) | 단장 결정(2026-09-10): 원본처럼 INT 가 패턴 수. 스탯 분배에 "수칙 공간"이 선택지로 들어간다. 레벨 기반안은 폐기 |
| 스킬 습득 | 스킬 포인트로 트리에서 구매. 선행 스킬 필요 | S4. 트리는 DAG, 데이터로 정의 |
| 전직 | 레벨 **20**, 1차 직업별 2개의 2차 직업 | ADR-003. 조건 레벨은 직업마다 18~22 로 차등 |

**패턴 슬롯이 핵심이다.** 레벨업의 가장 큰 보상은 스탯이 아니라 "패턴 하나 더"여야 한다.
이게 성장을 수칙 설계와 묶는 장치다.

### 3.4 스킬트리 (S4)

- 직업당 1차 스킬 6~8종 + 2차 직업당 4~5종. **M2 총 약 60종** (현재 18종)
- 신규 스킬은 전부 **이펙트 프리미티브 8종의 조합**으로 정의 — 프리미티브 추가가 필요하면 그때 엔진에 추가 (하드코딩 금지 원칙 유지)
- 2차 직업마다 **수칙 훅** 하나 (ADR-003): 끊기 특화 / 순서 조작 / 정밀 지휘(패턴 슬롯 +2) / 지속 피해 특화 등
- 소환·마법진은 M2 에서도 **제외** (엔진 엔티티 수명주기 추가가 큼 — M3 검토)

### 3.5 장비 (S7)

- 슬롯 3개: **무기 · 방어구 · 장신구** (원본의 세분화 타입 — 한손/양손/방패 — 는 M3)
- 직업별 장착 가능 무기 타입 화이트리스트 (검·단검·지팡이·성물·활)
- 장비 = 스탯 가산 + **특성 0~1개**. 특성은 수칙 설계와 맞물리는 것만:
  - 예: "시전 시간 −20%", "엄호 시 받는 피해 −15%", "후열 대상 피해 +10%", "행동 게이지 시작 +200"
  - 단순 "+공격력" 만 있는 특성은 만들지 않는다 — 그건 스탯이 한다
- **강화**: +0 ~ +5 (M2). 성공률 100/100/80/60/40/25%. **실패해도 파괴·하락 없음** (S7 결정 유지)
- 아이템 인스턴스는 정규화된 객체 `{ base, refine, trait }` — 원본의 문자열 인코딩 안 함

### 3.6 제작 · 공방 (S8)

- 재료 → 장비 제작. 레시피는 데이터
- 제작 시 특성 부여 확률 30%. 특성은 후보 풀에서 무작위 — **여기가 M2 의 유일한 "뽑기"** 이며 유료 재화와 절대 연결하지 않는다 (ADR 3.3)
- 강화 재료 = 금 + 공통 재료. 재료는 의뢰 드롭

### 3.7 경제 (S9 — 거래소 제외)

- 재화 **금 1종**. 재료 아이템 5~6종
- 상점: 기본 장비·소모품 구매, 아이템 판매(구매가의 20%)
- **싱크(소각처)를 처음부터**: 고용비, 강화비, 제작비, 이름 변경비. 원본의 인플레 문제 대응
- 거래소(플레이어 간)는 M3 — 플레이어가 한 명이라 의미 없음

### 3.8 의뢰 · 지역 (S12)

- 지역 **8곳** (M2). 권장 레벨 밴드 표시. 순차 해금 (직전 지역 3회 승리)
- 지역마다 등장 몬스터 **가중치 테이블** (합 정규화 안 함), **숨김 몬스터** 1종 (S12 채택)
- 몬스터 드롭: 만분율 테이블, 1개만 (S12 채택)
- 보상: 경험치·금은 몬스터 데이터, 재료는 드롭 테이블
- **행동력 없음** (M2). 싱글 로컬에서 시간 제한은 의미가 없고, 서버 도입 시 재검토

### 3.8b M2-1 구현 기록 (2026-09-10)

- **저장**: `apps/web/src/game/save.ts` — `GameSave{version:1, gold, members[], party[5], regionWins, battles}`. `migrate()` 가 형태 검증·기본값 보정. 내보내기/가져오기(JSON 텍스트)·새 게임 — 단원 탭 "저장 관리"
- **경험치**: `progression.ts` — `EXP_TABLE` (floor(40·L^1.6) 를 미리 계산한 정수 표, 레벨 30 까지 누적 101,971), `grantExp` 다중 레벨업·이월, 레벨당 스탯 5·스킬 2 포인트
- **성장 스탯**: `growthStats` — HP +5%/레벨, SP +3%/레벨 + INT 분배×2, 분배 스탯 상한 150, DEF/MDEF 는 직업 기본값(장비는 M2-4)
- **몬스터**: `data/monsters.ts` 10종 — 탈영병·탈영 궁수 / 도적단 단검수·궁수·**두목(숨김)** / 경쟁 용병 5직업(프리셋 수칙 그대로). `monsterSetup` 이 직업 프리셋을 레벨 성장(`growth`)으로 스케일. **짐승·괴물은 M2-5** (단장 결정: 궁극적으로 둘 다)
- **지역**: `data/regions.ts` 3곳 — 마을 외곽(Lv1–3, 2~3명) → 가도(Lv3–6, 3~4명, 3승 해금) → 폐허 요새(Lv6–10, 4~5명, 3승 해금). 가중치 조우, 같은 시드 = 같은 편성. 보상: 승리 전액 / 패배 경험치 30%·금 0
- **화면**: 탭을 **과제 · 의뢰 · 단원 · 수칙 · 훈련장** 5개로 재편. 편성은 단원 탭으로, 자유 전투는 훈련장으로 합침. 수칙 편집기는 이제 성장 스탯(INT)으로 패턴 수 상한을 계산
- **검증**: 레벨 1 기본 편성이 마을 외곽 ≥16/20 승, 폐허 요새 ≤6/20 승 — 권장 레벨이 실제로 의미 있음 (테스트로 고정)

### 3.9 몬스터 (신규)

- 현재 5직업 재사용은 한계. **몬스터 원형 8종** 필요: 잡몹형 / 돌격형 / 방벽형 / 사격형 / 주술형(시전) / 독형 / 소환 없이 다수형 / 보스형

  (초반 잡몹: "항상 → 공격" / 후반: "아군 시전 중 → 엄호 전환" 같은 것)
  → 몬스터 수칙 자체가 플레이어에게 **교재**가 된다
- 리소스: 몬스터 아이콘 SVG 8종 (자체 제작, [06 리소스 목록](06_리소스_목록.md) 갱신)
