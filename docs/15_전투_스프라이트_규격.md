## 1. 왜 이 방식인가

### 왜 도트인가

단장 결정이다. 덤으로 1인 개발에 유리하다 — 48×64 격자 안에서는 **"잘 그렸나"가 아니라 "읽히나"**가 기준이 되고,
그 기준은 사람이 눈으로 바로 판정할 수 있다.

### 왜 부위를 나누는가

| 방식 | 비용 | 판정 |
|---|---|---|
| **A. 부위 분리 + 포즈 3장** ✅ | 캐릭터당 `.px` **1장**. 애니메이션은 CSS 로 **한 번만** 쓰고 전원이 공유 | **채택** |
| B. 프레임 스프라이트 시트 | 캐릭터 × 동작 × 프레임. 13캐릭터 × 5동작 × 4프레임 = 260장 | 1인 개발에서 유지 불가 |
| C. 지금처럼 아이콘만 | 추가 비용 0 | 멈춰 있는 그림 — 단장이 원하지 않는 것 |

### 왜 회전을 안 쓰는가 — 이게 이 규격의 핵심이다

벡터 캐릭터라면 팔을 `rotate(-70deg)` 로 휘두르면 된다. **도트에서는 그러면 안 된다.**
회전된 픽셀은 브라우저가 다시 샘플링하면서 **가장자리가 뭉개지고 계단이 어긋난다.** 도트처럼 안 보인다.

그래서 이렇게 한다.

| 허용 | 왜 |
|---|---|
| **포즈 갈아 끼우기** (opacity 0/1 의 **딱딱한** 전환) | 픽셀이 그대로다. 이게 주 수단이다 |
| **정수 픽셀 이동** (`translateX(10px)`) | 픽셀이 그대로다 |
| **좌우 반전** (`scaleX(-1)`) | 픽셀이 그대로다. 적 팀에 쓴다 |
| **90도 회전** | 픽셀이 그대로다. 전사(쓰러짐)에 쓴다 |
| **밝기·채도 필터** | 픽셀 격자를 건드리지 않는다 |

| 금지 | 왜 |
|---|---|
| 90도의 배수가 아닌 회전 | 픽셀이 뭉개진다 |
| 정수가 아닌 배율 (`scale(1.08)`) | 픽셀이 뭉개진다 |
| `opacity` 의 **부드러운** 전환 | 두 포즈가 겹쳐 반투명 잔상이 남는다. 키프레임에서 24.9% → 25% 처럼 **끊어서** 쓴다 |
| `blur` · `drop-shadow` | 도트가 아니게 된다 |

## 2. 엠블럼 아이콘은 그대로 둔다

두 층을 **함께** 쓴다. 서로 대체하지 않는다.

| | 쓰는 곳 | 규격 |
|---|---|---|
| **엠블럼 아이콘** *(이미 있음)* | 목록 · 편성 판 · 도감 · 상점 — 작고 많은 곳 | `assets/jobs/*.svg`, `assets/monsters/*.svg`. viewBox 128, 배경 원, 벡터 |
| **도트 스프라이트** *(새로)* | **전투 스테이지에서 서서 움직이는 것** | `assets/units/*.px` → `.svg`. 48×64, 배경 없음 |

`.svg` 가 없는 캐릭터는 화면이 알아서 엠블럼으로 물러선다 (`UnitSprite`). **하나씩 만들어 가며 교체할 수 있다.**

## 3. 규격

### 캔버스와 방향

```
48 칸 × 64 칸.  1 문자 = 1 픽셀.
3/4 반측면.  몸을 화면 오른쪽으로 비스듬히 튼다.
적 팀은 화면이 알아서 좌우 반전한다 — 왼쪽을 보는 그림은 그리지 않는다.
머리 꼭대기  y = 0 부근
머리 아래    y = 24 부근
몸통         y 25 ~ 59
발바닥       y = 59       그림자 y = 60~62
좌우 중심선  x = 24
```

**정면으로 그리지 말 것.** 납작해 보인다. 3/4 는 이렇게 만든다.

| | 화면 오른쪽 (가까운 쪽) | 화면 왼쪽 (먼 쪽) |
|---|---|---|
| 무엇이 오나 | **무기 든 팔** | **방패 · 보조 장비** |
| 어깨 | 크고 낮다 | 작고 높다. 몸통에 일부 가린다 |
| 눈 | 얼굴 가장자리에 눌려 좁다 | 온전한 폭 |
| 발 | 앞으로 내민다 (`y=59`) | 뒤에 둔다 (한 칸 높게) |

코(투구의 코 가리개)는 얼굴 중심보다 **오른쪽으로 밀린다.** 이게 3/4 로 읽히게 하는 가장 큰 신호다.

화면에서는 **폰 1배(48×64), 데스크톱 2배(96×128)** 로만 쓴다. 정수 배율이라 픽셀이 보존된다.

### `.px` 파일 형식

```
# 전사                     <- 첫 주석 줄이 <title> 이 된다. 한국어 이름
# 아무 메모나 더 써도 된다

@palette
. none                     <- 반드시 '.' 를 투명으로 둘 것
k #1d1d24                  <- 문자 한 글자 + 공백 + #RRGGBB
s #cfd6e0

@layer shadow
(48자 × 64줄)
@layer arm-back
(48자 × 64줄)
```

- 줄이 48자보다 짧으면 나머지는 투명으로 채워진다. **오른쪽 끝 점은 생략해도 된다**
- 레이어는 **전부 같은 64줄**이어야 한다. 한 레이어라도 어긋나면 부위가 따로 논다
- **상자와 격자는 다르다.** 화면이 배치에 쓰는 **상자**는 언제나 48×64 다. 격자는 상자보다 넓어도 된다 —
  찌르기·활처럼 멀리 뻗는 무기가 있을 때. 그때는 `@canvas 48x64` 와 `@origin <n>` (상자의 x=0 이 격자 몇 번째 칸인지)을
  팔레트 앞에 적는다. 상자 밖 부분은 화면에서 그대로 삐져나와 그려진다 (`overflow: visible`). 잘라 내지도 줄이지도 않는다.
  `@canvas` 가 없으면 격자 크기가 곧 상자다 (손으로 그린 전사처럼 48칸일 때)
- 굽기: `node assets/build-units.mjs` — `assets/units/` 의 모든 `.px` 를 한 번에 굽는다

### 레이어 — 이름이 고정이다. 바꾸지 말 것

컴파일러(`build-units.mjs`)와 CSS 가 이 이름으로 찾는다. 뒤에서 앞 순서로 그린다.

| 레이어 | 무엇 | 필수 | 화면이 주는 움직임 |
|---|---|---|---|
| `shadow` | 바닥 그림자 | 아니오 | 움직이지 않는다 (발이 떠 보이지 않게) |
| `arm-back` | **뒤쪽 팔 · 방패 · 보조 장비** | 아니오 | 몸통과 함께 숨 쉰다 |
| `body` | **몸통 · 다리 · 허리** | **예** | 숨 쉰다 |
| `head` | 머리 · 투구 · 얼굴 | 아니오 | 몸통 안에 들어간다 — 몸이 움직이면 따라간다 |
| `arm0` | **무기 든 팔 — 대기 포즈** | 아니오 | 평소에 보이는 것 |
| `arm1` | **무기 든 팔 — 치켜든 포즈** | 아니오 | 공격 전반, 시전 중 계속 |
| `arm2` | **무기 든 팔 — 내리친 포즈** | 아니오 | 공격 후반 |

**또는** 전신을 통째로 갈아 끼우는 방식을 쓸 수 있다. 둘을 한 파일에 섞을 수 없다 (`build-units.mjs` 가 막는다).

| 레이어 | 무엇 | 언제 쓰나 |
|---|---|---|
| `pose0` `pose1` `pose2` | **전신 3장** (대기 / 치켜듦 / 내리침) | **이미지 생성 AI 에게 맡길 때.** AI 에게 부위를 나눠 그리게 하면 칸마다 어깨 위치가 달라져 팔이 순간이동한다 |

전신 방식에서도 `shadow` 는 따로 둔다 — 그림자는 움직이지 않아야 발이 떠 보이지 않는다.

- **필수는 `body` 하나뿐이다.** 나머지는 있으면 움직이고 없으면 그냥 안 움직인다
- 포즈 세 장은 **같은 팔이 세 가지 자세로 있는 것**이다. 어깨가 붙는 지점은 셋이 같아야 자연스럽다
- 사람 아닌 것(거미 · 박쥐 떼 · 거북)은 팔을 빼고 `body` + `head` 만 써도 된다.
  다만 **무기 팔이 없으면 공격 동작이 안 보인다** — 그럴 땐 `arm0/1/2` 에 "입을 벌린다 / 발톱을 든다" 같은 걸 담는다

컴파일 결과 SVG 구조 (CSS 가 이걸 찾는다):

```
<g class="p-shadow">      <- shadow
<g class="p-arm-back">    <- arm-back
<g class="p-torso">       <- body
  <g class="p-head">      <- head (몸통 안)
<g class="p-arm-front">   <- arm0/1/2 가 각각
  <g class="f f0">
  <g class="f f1">
  <g class="f f2">
```

전신 방식은 `p-arm-front` 자리에 `p-frames` 가 온다. 안쪽의 `f0/f1/f2` 는 같다 — CSS 가 그대로 쓴다.

### 그림 규약

| 항목 | 값 |
|---|---|
| 외곽선 | **1픽셀**, `#1d1d24` (`k`). 실루엣 바깥을 빙 두른다 — 이게 한 세트로 보이게 하는 가장 큰 요소 |
| 색 수 | 캐릭터당 **8~12색**. 한 재질당 밝은 색 + 어두운 색 두 단계면 충분하다 |
| 명암 | **왼쪽 위에서 빛이 온다**고 가정. 아래쪽·오른쪽이 어둡다 |
| 피부 | `#e8c39e` (밝음) / `#c08a5e` (그늘) — 사람 계열 공통 |
| 비율 | **머리가 전신의 1/3** 정도. 얼굴이 읽혀야 누군지 안다 |
| 얼굴 | 눈은 2×3 픽셀 덩어리. 열셋이 **같은 방식**이어야 한다 |
| 금지 | 그라디언트 · 반투명 가장자리 · 텍스트 · 1픽셀 외톨이 점 |

**팔레트 문자 관례** (지켜 주면 캐릭터끼리 비교하기 쉽다):

| 문자 | 뜻 | 전사의 값 |
|---|---|---|
| `.` | 투명 | — |
| `k` | 외곽선 | `#1d1d24` |
| `w` `s` `S` | 금속 — 밝음 / 중간 / 그늘 | `#eef2f7` `#cfd6e0` `#8fa3b8` |
| `f` `F` | 피부 — 밝음 / 그늘 | `#e8c39e` `#c08a5e` |
| `r` `R` | 대표색 — 밝음 / 그늘 | `#b23a48` `#7d2632` |
| `l` `L` | 가죽 — 밝음 / 그늘 | `#8a7550` `#5e4f36` |
| `d` | 그림자 | `#c9c0ad` |

**대표색(`r`/`R`)은 엠블럼 아이콘의 `color` 를 쓴다** (`assets/manifest.json`) — 같은 상대로 읽히게.

## 4. 화면이 주는 움직임 (파일에 넣지 말 것)

`apps/web/src/styles.css` 의 "도트 전투 스프라이트" 절에 있다. 엔진이 내는 전투 이벤트에 그대로 물려 있다.

| 상태 | 언제 | 무엇이 움직이나 |
|---|---|---|
| **대기** | 항상 | 몸통·머리·양팔이 **1픽셀** 위아래 (`px-breathe`) |
| **공격** | `ruleFired` · `damage` | 앞으로 **10픽셀** 내딛고, 팔 포즈가 **f0 → f1 → f2 → f0** 로 갈린다 |
| **시전** | `castStart` ~ `castResolve` | 팔이 **f1**(치켜듦)로 고정되고 전체가 밝아진다 |
| **피격** | `damage` 를 맞음 | 뒤로 6픽셀 밀리고 한 번 하얗게 번쩍한다 |
| **전사** | `death` | **90도 회전**해 쓰러지고 회색이 된다 |

**SVG 파일에 애니메이션을 넣지 말 것.** `<animate>` · `<style>` · `style="animation"` 전부 금지.
새 동작이 필요하면 CSS 에 키프레임을 더한다 — **그림을 다시 그릴 필요가 없다.**

## 4.5 디자인 콘셉트 — 어디까지 맡기는가

캐릭터 열세 명이 **한 세트로 보이는 것**이 개별 캐릭터가 멋있는 것보다 중요하다.
그래서 경계를 나눠 둔다.

### 이미 정해졌다 — 바꾸지 말 것

| 항목 | 값 | 왜 |
|---|---|---|
| 캔버스 · 시점 | 48×64, **3/4 반측면**(오른쪽) | 배치·반전·2배 확대가 여기 의존한다 |
| 레이어 이름 | 3절 표 | 컴파일러와 CSS 가 이 이름으로 찾는다 |
| 원본 형식 | `.px` 문자 격자 | `.svg` 를 직접 그리면 다음 빌드에 덮어써진다 |
| 회전 금지 | 1절 | 도트가 뭉개진다 |
| 외곽선 | 1픽셀 `#1d1d24` | 한 세트로 보이게 하는 가장 큰 요소 |
| 대표색 | 엠블럼 아이콘의 `color` | 같은 상대로 읽혀야 한다 |
| 세계관 · 톤 | 판타지 용병단, 건조한 유머 ([03](03_세계관_톤.md)) | 이미 결정된 ADR |

### 맡긴다 — 에이전트가 정해도 되는 것

- 실루엣과 복장 디테일 (도적의 후드 모양, 마법사 로브 길이, 오우거의 어깨)
- 표정 처리 (눈·입을 어떻게 찍을지 — 다만 **열셋이 같은 방식**이어야 한다)
- 비율 미세 조정 (머리 크기, 다리 길이 — 발바닥 y=59 안에서)
- 몬스터의 구체적 생김새 (5절의 "인상" 한 줄을 지키는 선에서)
- 포즈 세 장을 무엇으로 할지 (활잡이라면 f0 내림 / f1 당김 / f2 놓음 처럼)
- 팔레트에 색을 **더** 넣는 것 (관례 문자 7종을 지키는 선에서)

### 먼저 물어볼 것 — 혼자 정하지 말 것

- **캔버스를 키워야 할 것 같을 때** (오우거·거북 등). 48×64 를 넘기면 정렬이 전부 영향을 받는다 → 규격을 고치는 문제다
- 레이어를 더 만들어야 할 때 (컴파일러와 CSS 를 같이 고쳐야 한다)
- 캐릭터의 성별·나이 같은 **설정에 해당하는 것**. 지금 정해진 것이 없고, 정하면 되돌리기 어렵다

### 순서

**한 명(도적)을 먼저 만들어 확인받고, 그 다음 나머지 열하나.**
열셋을 한 번에 만들면 방향이 어긋났을 때 열셋을 다 다시 만들어야 한다.

## 6. 나중

- **무기 교체를 그림으로**: 지금은 무기가 팔 포즈 안에 그려져 있다. 장비에 따라 갈아 끼우려면 레이어를 더 쪼개야 한다 — 리그가 다 갖춰진 뒤에
- **전직 10종**: 2차 직업이 설계되면 같은 규격으로 10장 추가
- **넉백 · 열 이동**: 지금은 제자리 흔들림. `moveRow` 를 실제 이동으로 보여줄 수 있다 (정수 픽셀 이동이라 도트가 안 깨진다)

## 7. 납품

1. `assets/units/<키>.px` 에 놓는다
2. `node assets/build-units.mjs` 를 돌린다 → `.svg` 가 나온다. **둘 다 커밋한다**
3. `assets/manifest.json` 의 `units` 에 한 줄, `assets/README.md` 원장에 **두 줄**(`.px` 원본, `.svg` 생성물)
4. 웹 코드는 건드리지 않아도 된다 — 파일이 있으면 자동으로 엠블럼 대신 쓰인다
5. 확인: `npm run dev` → 편성 탭 → 한 판 시험 → 재생. 숨 쉬고, 휘두르고, 맞으면 번쩍하는지 본다

### 검수 체크리스트

- [ ] `.px` 의 모든 레이어가 **정확히 64줄**이다
- [ ] **3/4 반측면**이다 — 정면으로 납작하지 않다
- [ ] 발바닥이 y=59, 좌우 중심이 x=24 — 다른 캐릭터 옆에 세웠을 때 키와 발높이가 맞는다
- [ ] 포즈 f0/f1/f2 의 **어깨가 붙는 지점이 같다** — 갈아 끼울 때 팔이 순간이동하지 않는다
- [ ] 생성된 `.svg` 안에 `<animate>` · `<style>` · `style="animation"` 이 **없다**
- [ ] 외곽선이 전부 1픽셀 `#1d1d24`. 그라디언트·반투명 없음
- [ ] 1픽셀 외톨이 점이 없다 (확대하면 먼지처럼 보인다)
- [ ] 48×64 원본 크기(폰)에서도 누군지 안다
- [ ] 기존 열두 명과 **한 세트로 보인다**
- [ ] `assets/README.md` 원장과 `manifest.json` 에 기록했다
