# 전투 스프라이트 규격 — 움직이는 캐릭터 (ADR-005)

- **결정일**: 2026-09-11 (단장 요청 — "HOF처럼 멈춰 있는 그림이 아니라 유니콘 오버로드처럼")
- **결론**: **부위 분리 SVG 리그 + CSS 애니메이션**. 프레임 애니메이션을 그리지 않는다.
- **참조 구현**: [`assets/units/warrior.svg`](../assets/units/warrior.svg) — 이 파일이 규격의 정본이다. 새 캐릭터는 이걸 복사해서 시작한다.

## 1. 왜 이 방식인가

유니콘 오버로드(바닐라웨어)가 살아 있어 보이는 이유는 프레임을 많이 그려서가 아니다.
**캐릭터를 부위로 나눠 그리고, 그 부위를 뼈대처럼 움직이기** 때문이다. 오딘 스피어 때부터 이어 온 그들의 방식이다.
우리는 같은 발상을 SVG + CSS 로 한다. 규모만 작을 뿐 원리는 같다.

| 방식 | 비용 | 판정 |
|---|---|---|
| **A. 부위 분리 리그** ✅ | 캐릭터당 SVG **1장**. 애니메이션은 CSS 로 **한 번만** 쓰고 전원이 공유 | **채택** |
| B. 프레임 스프라이트 | 캐릭터 × 동작 × 프레임. 13캐릭터 × 5동작 × 3프레임 = 195장 | 1인 개발에서 유지 불가 |
| C. 지금처럼 아이콘만 | 추가 비용 0 | 멈춰 있는 그림 — 단장이 원하지 않는 것 |

A 의 덤:
- **장비를 그림으로 보여줄 수 있다.** `p-weapon` 부위만 갈아끼우면 장검을 든 전사가 된다 (M2-4 와 바로 이어진다)
- 애니메이션을 고치면 **전 캐릭터가 동시에 좋아진다**
- 파일 하나가 3KB 안쪽이라 13종을 다 받아도 40KB

## 2. 엠블럼 아이콘은 그대로 둔다

두 층을 **함께** 쓴다. 서로 대체하지 않는다.

| | 쓰는 곳 | 규격 |
|---|---|---|
| **엠블럼 아이콘** *(이미 있음)* | 목록 · 편성 판 · 도감 · 상점 — 작고 많은 곳 | `assets/jobs/*.svg`, `assets/monsters/*.svg`. viewBox 128, 배경 원 |
| **리그 스프라이트** *(새로)* | **전투 스테이지에서 서서 움직이는 것** | `assets/units/*.svg`. viewBox 96×128, 배경 없음 |

리그가 없는 캐릭터는 화면이 알아서 엠블럼으로 물러선다 (`UnitSprite`). **하나씩 만들어 가며 교체할 수 있다.**

## 3. 규격

### 캔버스와 방향

```
viewBox="0 0 96 128"   width="96" height="128"
오른쪽을 본다 (+x 방향). 적 팀은 화면이 알아서 좌우 반전한다
발바닥  y = 126        그림자는 y ≈ 124
```

### 관절 좌표 — **전 캐릭터 공통. 바꾸지 말 것**

애니메이션 CSS 가 이 좌표를 회전축으로 쓴다. 어긋나면 팔이 어깨가 아닌 데서 돌아간다.

| 관절 | 좌표 | 회전축이 되는 부위 |
|---|---|---|
| 엉덩이 | `48, 86` | `p-torso` |
| 어깨 | `48, 58` | `p-arm-front`, `p-arm-back` |
| 목 | `48, 48` | `p-head` |
| 다리 붙는 곳 | `48, 84` | `p-leg-front`, `p-leg-back` |
| 손 (무기 쥐는 곳) | `62, 62` 부근 | `p-weapon` |

### 부위 클래스 — **id 가 아니라 class** (한 화면에 열 명이 나온다)

뒤에서 앞 순서로 그린다.

```
p-shadow      바닥 그림자 (선택)
p-leg-back    뒤 다리
p-arm-back    뒤 팔   └ p-offhand  방패·보조 장비 (선택)
p-torso       몸통    └ p-head     머리 (몸통 안에 넣는다 — 몸이 기울면 머리도 따라간다)
p-leg-front   앞 다리
p-arm-front   앞 팔   └ p-weapon   무기 (선택)
```

- **필수는 `p-torso` 하나뿐이다.** 나머지는 있으면 움직이고 없으면 그냥 안 움직인다
- 사람 아닌 것(거미 · 박쥐 떼 · 거북)은 팔다리를 빼고 `p-torso` + `p-head` 만 써도 된다.
  거미 다리처럼 여러 개면 `p-arm-back` / `p-arm-front` 에 나눠 담아 흔들리게 한다
- **애니메이션을 SVG 파일에 넣지 말 것.** `<animate>` · `<style>` · `style="animation"` 전부 금지.
  움직임은 전부 웹의 CSS 가 준다

### 그림 규약

| 항목 | 값 |
|---|---|
| 외곽선 | `#1d1d24`, 굵기 3 (96×128 기준). `stroke-linejoin="round"` |
| 색 | 팔레트(`assets/manifest.json`)에서. 캐릭터당 3~5색 |
| 피부 | `#e8c39e` (사람 계열 공통) |
| 금지 | 그라디언트 · 필터 · 그림자 효과 · 텍스트 · 래스터 이미지 |
| 첫 자식 | `<title>한국어 이름</title>` |
| 비율 | 머리를 크게 (전신의 1/4 정도). 40~70px 로 줄여도 누군지 알아야 한다 |

## 4. 화면이 주는 움직임 (파일에 넣지 말 것)

엔진이 내는 전투 이벤트에 그대로 물려 있다.

| 상태 | 언제 | 무엇이 움직이나 |
|---|---|---|
| **대기** | 항상 | 몸통이 숨 쉬고, 머리가 따라 흔들리고, 뒤 팔이 살짝 흔들린다 |
| **공격** | `ruleFired` · `damage` | 몸 전체가 앞으로 내딛고, 앞 팔이 크게 휘두르고, 몸통이 기운다 |
| **시전** | `castStart` ~ `castResolve` | 앞 팔을 들고 유지, 전체가 보라색으로 빛난다 |
| **피격** | `damage` 를 맞음 | 흔들리고 한 번 번쩍한다 |
| **전사** | `death` | 옆으로 쓰러지고 회색이 된다 |

새 동작을 넣고 싶으면 `apps/web/src/styles.css` 의 `/* 전투 리그 스프라이트 */` 절에 키프레임을 더한다.
**그림을 다시 그릴 필요가 없다.**

## 4.5 디자인 콘셉트 — 어디까지 맡기는가

캐릭터 열세 명이 **한 세트로 보이는 것**이 개별 캐릭터가 멋있는 것보다 중요하다.
그래서 경계를 나눠 둔다.

### 이미 정해졌다 — 바꾸지 말 것

| 항목 | 값 | 왜 |
|---|---|---|
| 관절 좌표 | §3 표 | 어긋나면 팔이 어깨 아닌 데서 돌아간다 |
| 부위 클래스 이름 | `p-*` | CSS 가 이 이름으로 찾는다 |
| 캔버스 · 방향 | 96×128, 오른쪽 | 좌우 반전과 배치가 여기 의존한다 |
| 팔레트 | `manifest.json` 의 `palette` | 화면 전체가 이 색으로 맞춰져 있다 |
| 캐릭터 대표색 | 엠블럼 아이콘의 `color` | 같은 상대로 읽혀야 한다 |
| 세계관 · 톤 | 판타지 용병단, 건조한 유머 ([03](03_세계관_톤.md)) | 이미 결정된 ADR |
| 외곽선 · 굵기 | `#1d1d24`, 3 | 한 세트로 보이게 하는 가장 큰 요소 |

### 맡긴다 — 에이전트가 정해도 되는 것

- 실루엣과 복장 디테일 (도적의 후드 모양, 마법사 로브의 주름, 오우거의 어깨 형태)
- 표정 처리 (눈을 점으로 할지 선으로 할지 — 다만 **열셋이 같은 방식**이어야 한다)
- 비율 미세 조정 (머리 크기, 팔다리 길이 — §3 관절 좌표 안에서)
- 몬스터의 구체적 생김새 (규격의 "인상" 한 줄을 지키는 선에서)
- 부위를 더 나눌지 (예: 거미 다리를 여섯 개로 쪼개 각각 흔들리게)

### 먼저 물어볼 것 — 혼자 정하지 말 것

- **관절 좌표를 바꿔야 할 것 같을 때** (네 발 짐승 등). 바꾸면 애니메이션 전체가 영향을 받는다 → 규격을 고치는 문제다
- 팔레트에 없는 색이 꼭 필요할 때
- 캐릭터의 성별·나이 같은 **설정에 해당하는 것**. 지금 정해진 것이 없고, 정하면 되돌리기 어렵다
- 새 부위 클래스를 만들어야 할 때 (CSS 를 같이 고쳐야 한다)

### 순서

**한 명(도적)을 먼저 만들어 확인받고, 그 다음 나머지 열하나.**
열셋을 한 번에 만들면 방향이 어긋났을 때 열셋을 다 다시 만들어야 한다.
