## 1. 기술 규약

> **2026-09-13 단장 결정:** 캐릭터·몬스터 스프라이트와 한 세트로 보이도록 아이콘도 전부 도트 형식으로 통일한다.

> **2026-09-14 단장 결정: "제로식 수준까지."** 규격을 24×24 · 1배 표시로 바꾼다 (아래 "왜 24×24 인가").

> **2026-09-14 단장 결정: "리소스는 현재 웹 게임에 반영된 JRPG 도트 버전으로 가야할 것 같아요."**
> 지금 게임에 들어간 87종(AI 원본 → `tools/process-jrpg-icon.py` 24×24 변환, 커밋 `fbde2df`)이 **최종**이다.
> 손으로 다시 찍는 재작업(§9)은 두 번 시도했고 두 번 모두 JRPG 느낌을 지워 **보류**했다 — 단장: "나중에 개선하던가 하겠음".

**만드는 방법은 87종과 같다.** JRPG 도트풍 AI 원본을 만들고(docs/19 §2 공통 프롬프트), `tools/process-jrpg-icon.py` 로 24×24 로 변환한 뒤
`tools/check-icons.py` 를 통과시킨다. 변환본을 손으로 다시 찍어 단순하게 만들지 않는다.

| 항목 | 값 |
|---|---|
| 형식 | 투명 배경 RGBA PNG. **알파는 0 또는 255 뿐** (반투명 금지) |
| 게임용 크기 | **24×24px.** 주 피사체는 22×22 안 — 사방 1px 이상 비운다 |

| 외곽선 | 실루엣 바깥에 **손으로 찍은 1px 어두운 테두리.** 재질별로 어두운 갈색·남색 계열, 순수 검정 한 색으로 뭉개지 않는다. 필터로 만든 테두리는 쓰지 않는다 (아래) |
| 굵기 | **가는 물체(검날·지팡이·활·화살·깃털)도 2px 이상.** 1px 대각선은 1배에서 사라진다 |
| 색 수 | **목표 8~10색**, 검사기 한도 **6~12색**. 재질별 밝음·기본·그늘 세 단계. 그라디언트·흐림·안티앨리어싱 금지 |
| **JRPG 느낌 (필수)** | 단장: *"JRPG 느낌이 사라지면 안됩니다."* — 규격을 다 지켜도 이것이 없으면 반려다. 아래 다섯을 모두 갖춘다 |
| 형태 | 한 아이콘에 상징 **하나.** 궤적·반짝임·두 번째 물체는 24px 에서 잡티가 된다 |
| 텍스트 | 금지. 글자 없이 형태만으로 구분되어야 한다 |
| 원본 위치 | AI 로 초안을 만들었다면 `art-source/icons/<종류>/<id>-source.png` — 배포 폴더 밖, 채택본만 커밋 |
| 검사 | **납품 전 `python tools/check-icons.py` 통과 필수** — 크기·반투명·여백·색 수를 어기면 실패 |

### JRPG 느낌 — 무엇을 갖춰야 하나 (필수)

"작고 선명한 아이콘"과 "JRPG 아이콘"은 다르다. 앞의 것은 앱 아이콘에도 있다. 이 게임이 원하는 것은 뒤의 것이다.

| # | 갖출 것 | 없으면 이렇게 된다 |
|---|---|---|
| 1 | **실물을 그린다.** 검·약병·깃털·부적처럼 손에 쥘 수 있는 물건, 또는 그 물건을 쓰는 순간. 기호(＋ · X · 화살표만 있는 도형)로 대신하지 않는다 | UI 스티커 |
| 2 | **재질마다 3단 명암 + 하이라이트 한 점.** 금속은 반짝이는 흰 점, 나무는 결, 가죽은 어두운 테. 빛은 왼쪽 위 | 평면 |
| 3 | **색이 따뜻하고 풍부하다.** 8~10색. 외곽선은 재질색을 어둡게 한 색 — 모든 테두리를 한 검정으로 두르지 않는다 | 흑백 만화 |
| 4 | **입체로 놓는다.** 칼·지팡이는 비스듬히, 병·부적은 약간 위에서 본 3/4. 완전한 정면·측면 실루엣 하나로 끝내지 않는다 | 픽토그램 |
| 5 | **장식 한두 개.** 날밑의 보석, 손잡이에 감은 천, 부적의 끈. 24px 에서도 보이는 크기로 | 싸구려 소품 |

판정 방법: **손대지 않은 재변환본 옆에 나란히 놓았을 때 같은 세트로 보이는가.** 더 깨끗해야 하지만, 더 단순해 보이면 실패다.

### 왜 24×24 인가 — 제로식 실측 (2026-09-14)

제로식 라이브 서버의 스킬·장비 아이콘 19종을 재 보았다 (규격만 참고했다. 그림은 보지도 가져오지도 않는다 — §0).

| | 크기 | 화면 표시 | 색 수 (중앙) | 외톨이 픽셀 (중앙) |
|---|---|---|---|---|
| 제로식 | 24×24 | 24px — 1배 | 9 | 10% |
| 우리 납품본 (2026-09-13) | 32×32 | 24·20px — 0.75·0.625배 | 236 | 78% |
| 우리 재변환본 (2026-09-14, 지금) | 24×24 | 24·48px — 1·2배 | 10 | 25% |

흐렸던 원인은 둘이다. ① 정수가 아닌 배율로 줄여 보였다 ② 그림 자체가 도트가 아니었다 — AI 원본을 최근접으로만 줄여 픽셀마다 조금씩 다른 색이 찍혔다.
외톨이 픽셀 = 상하좌우 이웃 전부와 색이 다른 픽셀. 많을수록 1배에서 뿌옇게 보인다.

재변환(`tools/process-jrpg-icon.py` — 면적 평균 축소 → 10색 → 외톨이 정리)으로 ①과 색 수는 풀렸다.
**남은 차이 — 외곽선과 단순한 형태 — 는 도구로 만들 수 없다.** 필터로 바깥 테두리를 두르면 가는 대각선이 덩어리가 되고,
안쪽 테두리는 칼날을 어둡게 하고 빛을 죽인다. 어두운 스킬 프레임 안에서는 둘 다 보이지도 않는다.
그래서 §9 에서 손으로 다시 그리려 했지만 **선명해지는 대신 평면 스티커가 되어 JRPG 느낌을 잃었다** (§9-1). 단장 결정으로 보류하고 **지금은 재변환본으로 간다.**

기존 벡터 아이콘을 격자로 변환하던 방식은 폐기했다. 화풍의 승인 기준은
`art-source/icon-drafts/jrpg-style-proof.png`의 파이어볼·참나무 지팡이 시안이다 (크기는 위 규격을 따른다).

### 배경 없이 실루엣과 색으로 종류를 구분한다

| 종류 | 표현 |
|---|---|---|
| **스킬** | 공격 궤적·마법 효과·행동을 단일 상징으로 표현 |
| **장비 · 재료** | 물체 하나만 분명하게 표현. 같은 장비 계열은 등급에 따라 장식과 재질이 발전 |
| **상태이상** | 12~16px에서도 읽히는 단순하고 강한 상태 상징 |
| **특성** | 효과를 대표하는 물체 또는 행동 상징. 육각 배경을 강제하지 않음 |

### 검수 기준

- **JRPG 느낌 다섯 가지를 모두 갖췄는가** (위 표). 가장 먼저 본다 — 여기서 떨어지면 나머지는 보지 않는다
- **`python tools/check-icons.py` 통과.** 실패가 하나라도 있으면 납품하지 않는다. 외톨이 경고(35% 초과)도 원칙적으로 고친다. 6색 미만은 실패다 (평면 스티커)
- **24px(1배)에서 서로 구분되는가.** 판단은 1배로 한다 — 48px 로 크게 보면 괜찮아 보여도 실제 목록·슬롯은 24px 다
- 밝은 바탕(`#f3f0ea`)과 어두운 바탕(`#1d1d24`) 양쪽에서 실루엣이 보이는가. 스킬은 어두운 프레임 안에 들어간다
- 같은 종류끼리 한 세트로 보이는가 (굵기·여백·비율)
- 미리보기: `node tools/build-preview.mjs` → `tools/preview.html`.
  새 종류를 추가했다면 이 스크립트도 함께 확장한다

### 규약 — §1 에 더해 이번에 정한 두 가지

| 항목 | 값 |
|---|---|
| 경로 | `assets/regions/<지역 id>.png` · `assets/adventures/<모험 id>.png` |
| 원본 | `art-source/regions/<id>-source.png` · `art-source/adventures/<id>-source.png` — **채택본만 커밋** (`assets/README.md` 규칙) |

## 9. 재작업 요청 (2026-09-14) — 87종을 24px 손그림으로 · ⏸ **보류**

> **2026-09-14 단장 결정으로 보류한다.** *"리소스는 현재 웹 게임에 반영된 JRPG 도트 버전으로 가야할 것 같아요. 나중에 개선하던가 하겠음."*

> 나중에 다시 할 때는 §1 "JRPG 느낌" 다섯 가지와 §9-1 의 2차 작업 기준을 먼저 지킨다. 아래는 그때를 위한 기록이다.

> 단장 결정: "제로식 수준까지 만드는게 좋을 것 같은데요."

87종은 2026-09-14 에 AI 원본에서 24×24 로 **기계 재변환**해 두었다 (docs/19 §5). 흐림은 풀렸고 검사기도 통과한다.
하지만 제로식과의 남은 차이 — **손으로 찍은 외곽선, 24px 에 맞춘 단순한 형태** — 는 사람이(에이전트가) 픽셀 단위로 다시 그려야 한다.

### 방식

1. **지금 `assets/<종류>/<id>.png` (24×24 재변환본)을 출발점으로 쓴다.** 구도·색은 이미 맞춰져 있다. 처음부터 새로 생성하지 않는다
2. 24×24 격자에서 픽셀 단위로 고친다 — 외곽선을 찍고, 잡티를 지우고, 가는 부분을 2px 로 굵히고, 상징을 하나로 줄인다
3. 제목·용도는 §2~§4 의 「그릴 것」 그대로다. **의미를 바꾸는 것은 아래 표에 적힌 것만**
4. `python tools/check-icons.py` 통과 → `node tools/build-preview.mjs` → 1배·밝은/어두운 바탕에서 확인
5. 파일을 덮어쓰고 `assets/README.md` 원장의 해당 줄 출처를 "24px 손질 (2026-MM-DD)"로 고친다. 새 AI 원본을 만들었다면 `art-source/` 원본도 교체한다
6. **한 번에 1순위만 납품한다.** 이쪽에서 화면을 보고 방향이 맞으면 2순위로 넘어간다 — 87종을 한꺼번에 덮어쓰지 않는다

### 무엇이 좋아졌나

- 1px 어두운 외곽선이 생겨 **어두운 바탕·프레임 안에서 실루엣이 선다** — 재변환본의 가장 큰 약점이 풀렸다

### 무엇이 틀렸나 — 남은 60종에 같은 방식을 쓰면 안 되는 이유

1. **원래 그림을 버리고 기호로 바꿨다.** §9 방식 1번 "구도·색은 이미 맞춰져 있다, 처음부터 새로 만들지 않는다"를 어겼다.

2. **JRPG 풍이 사라졌다.** 재질마다 3단 명암이 있던 그림이 2~3색 평면 스티커가 됐다. 손대지 않은 60종 옆에 서면 다른 세트다

4. **가는 선이 오히려 늘었다.** 활 3종·기본 공격·저격이 1px 선이라 어두운 바탕 24px 에서 거의 사라진다 (§1 "가는 물체도 2px 이상")
5. **서로 헷갈린다.** 방어 약화 · 방벽 · 철의 의지(장신구)가 전부 "X 무늬 방패"로 수렴했다
6. **그림이 작아졌다.** 대각선 막대 하나만 남아 22×22 칸을 절반도 채우지 않는다
