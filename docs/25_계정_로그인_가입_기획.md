## 3. 화면 흐름

```
접속
 │
 ├─ 세션 있음 ─────────────────────────────┐
 │                                          ▼
 ▼                                  서버에 저장 데이터가 있나?
[① 타이틀 · 로그인] ──로그인 성공──▶      ├─ 있음 → [본부]
 │                                          └─ 없음 → [③ 모험가 만들기] → 첫 저장 → [본부]
 └─ "새 계정 만들기"
     ▼
[② 가입] ──가입 성공(자동 로그인)──▶ [③ 모험가 만들기]
```

게임 안: 본부 상태줄에 `ID` 표시, **로그아웃**은 본부 탭. 비밀번호 변경·계정 삭제는 나중에 **설정**(§5).

## 4. 화면별 구성

### ① 타이틀 · 로그인
```
┌──────────────────────────────────────┐
│        [로고] 오더 앤 블레이드           │
│   규칙을 짜고, 용병단이 싸운다            │
├──────────────────────────────────────┤
│  ID        [____________]            │
│  비밀번호   [____________]            │
│  [✓] ID 기억하기                       │
│          [   로그인   ]                │
│  처음이신가요?  새 계정 만들기 →          │
├──────────────────────────────────────┤
│  게임 소개       — 본부 문답에서 옮김     │
│  단장의 임무      — 본부 문답에서 옮김     │
│  (선택) 샘플 전투 짧은 재생               │
├──────────────────────────────────────┤
│  (서버 뒤) 명예의 전당 상위 5 자리         │
│  공지 · 미접속 계정 정리 안내              │
└──────────────────────────────────────┘
```
- **게임 소개는 본부의 첫 방문 문답(`Home.tsx` 의 `faq`)을 옮긴다** (2026-09-15 단장 지시 — HOF·제로식처럼 로그인 전 화면에서 무슨 게임인지 보여준다).
  - 타이틀로 옮김: "게임 소개" · "단장의 임무" (2026-09-15 단장 문구) — 가입 전 사람이 알아야 할 소개.
  - 본부에 남김: "뭐부터?" · "수칙은 어디서 배우나?" — 모험가를 만든 직후에 필요한 안내. 제목도 용병단 이름 그대로.
- **ID 기억하기**는 ID 만 기억한다. 비밀번호는 브라우저 저장 기능에 맡긴다 (입력칸 `autocomplete` 지정).
- 로그인 유지(세션)는 기본으로 켠다 — 제로식처럼 매번 치지 않게.
- 전투 느낌 문답에는 훈련장 샘플 전투를 작게 자동 재생하면 가장 잘 팔린다 (엔진이 결정론이라 시드 하나로 됨). 선택 사항.

### ② 가입
```
  새 계정 만들기
  ID          [____________]  영문·숫자 4~20자
  비밀번호     [____________]  8자 이상
  비밀번호 확인 [____________]
  ⚠ 비밀번호를 잊으면 스스로 찾을 수 없습니다. 꼭 기억해 두세요.
  [✓] 위 안내를 확인했습니다
  [ 계정 만들기 ]   [ 돌아가기 ]
```
- 입력하는 동안 칸 옆에 규칙 충족 여부를 바로 표시 (빨강 → 초록). 누른 뒤에야 틀렸다고 알리는 HOF 방식은 피한다.
- ID 중복 확인은 "계정 만들기"를 누를 때 서버가 판정 (로컬 모드에서는 이 브라우저 안의 목록으로).

### ③ 모험가 만들기 (기존 `NewGame.tsx` 확장)
```
  새 모험
  용병단 이름  [____________]  1~12자        ← 새로 추가 (HOF 팀 이름)
  주인공 성별  [남 도트] [여 도트]            ← 있음
  주인공 이름  [____________]  1~12자        ← 있음
  시작 금 300
  [ 모험 시작 ]
```
- 용병단 이름은 저장의 `name` 칸이 이미 있다 (`DEFAULT_NAME = '이름 없는 용병단'`) — 입력만 붙이면 된다.
- 계정제에서는 **취소 버튼이 없다** — 이 화면을 끝내야 게임이 시작된다. 대신 로그아웃 링크 하나.

## 6. 저장과 예외

- **저장 시점**: 지금처럼 바뀔 때마다 저장하되, 서버로는 **몇 초 모아서** 보낸다. 창을 닫을 때 한 번 더.
- **상태줄 표시**: `저장됨 · 저장 중… · 연결 끊김(이 브라우저에 임시 보관)` 셋 중 하나.
- **두 기기 동시 접속**: 저장마다 "마지막 저장 시각"을 붙이고, 서버 쪽이 더 새로우면 덮지 않고 "다른 곳에서 진행한 기록이 있습니다 — 불러오기" 안내.
- **예전 브라우저 저장 옮기기**: 첫 로그인 때 이 브라우저에 `webrpg.game.v1` 이 있고 계정에는 기록이 없으면 "이 브라우저의 진행(Lv, 금)을 이 계정으로 가져올까요?" 한 번 묻는다. 거절하면 모험가 만들기로.
- **JSON 내보내기/가져오기**: 개발·백업용으로 남긴다. 단, 서버 판정 단계(§7 C)에서는 가져오기를 막는다 (조작 통로가 되므로).

## 7. 구현 순서

| 단계 | 내용 | 서버 필요 | 비고 |
|---|---|---|---|
| **A. 화면 먼저** | ①②③ 화면, 입력 검증, 흐름 연결. 인증 서비스 인터페이스(`signUp` · `signIn` · `signOut` · `loadSave` · `writeSave`)를 만들고 **로컬 모드** 구현을 붙인다 | 아니오 | 로컬 모드는 상태줄에 **"로컬 모드 — 이 브라우저에만 저장"** 을 항상 띄운다. 비밀번호는 로컬에서도 해시로만 보관 |
| **B. 서버 연결** | Supabase 프로젝트 → 인증 서비스의 서버 구현으로 교체. 저장 테이블 + "자기 줄만" 보안 규칙. §6 옮기기·충돌 처리 | 예 | 단장 준비물: Project URL · anon key |
| **C. 서버 판정** | 전투·보상·구매를 서버가 계산 (엔진 재사용). 랭킹·명예의 전당 | 예 | 랭킹·PvP 를 하려면 필수 |

A 단계만 끝나도 배포판에서 가입 → 모험가 만들기 → 본부 흐름을 직접 눌러 볼 수 있다. B 는 화면을 거의 안 건드리고 뒤만 바꾼다.

### 8.1 미접속 정리 — 언제, 어떻게 (초안)
- **왜 필요한가**: 서버 용량(무료 요금제 DB 500MB)과 **이름 선점**. 떠난 사람이 좋은 용병단 이름을 계속 쥐고 있게 된다.
- **언제 시작**: 둘 중 먼저 오는 쪽 — DB 사용량 70% 도달, 또는 "쓰고 싶은 이름이 방치 계정에 묶여 있다"는 요청이 반복될 때.
- **준비물 (B 단계에서 미리)**: 계정 줄에 `마지막 접속 시각`을 기록한다. 지금 안 적어 두면 나중에 기준을 세울 수 없다.
- **정리 기준 초안**: 1년 미접속 **이면서** 진행이 적은 계정(예: 주인공 Lv 10 미만)부터. 오래 키운 계정은 더 오래 보존.
- **삭제 전 단계**: 타이틀 공지로 30일 예고 → 기간 안에 로그인하면 해제 → 지나면 삭제. 이메일이 없어 개별 통보는 못 하므로 기준을 **가입 화면에 미리 적어 둔다** (제로식이 메인 화면에 적어 둔 방식).
- **이름만 먼저 풀어 주기**(대안): 계정은 남기고 용병단 이름만 "방치된 용병단#1234" 로 바꿔 이름을 돌려준다. 용량 문제가 아니라 이름 문제일 때 쓴다.
