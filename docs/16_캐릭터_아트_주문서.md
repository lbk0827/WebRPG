# 캐릭터 아트 주문서 — 이미지 생성 AI 에게 맡길 때의 규칙

- **결정일**: 2026-09-11 (단장 — "GPT한테 요청할까 합니다. 규칙만 정해주세요")
- **적용 대상**: [15_전투_스프라이트_규격.md](15_전투_스프라이트_규격.md) 의 13종 도트 캐릭터
- **한 줄 요약**: **GPT 가 그린 PNG 는 초안이다.** 최종 픽셀은 `assets/png-to-px.mjs` 가 만들고, 사람이 다듬는다

---

## 0. 절대 규칙 ⚠️ — 이걸 어기면 그림을 못 쓴다

1. **프롬프트에 기존 게임·캐릭터 이름을 쓰지 말 것.**
   `Hall of Fame` · `제로식` · 그 밖의 상용 게임 제목, 캐릭터 이름, 개발사 이름 전부다.
   "○○ 게임 스타일로" 라고 쓰는 순간 결과물이 그 게임의 2차적 저작물로 다투어질 수 있다.
2. **남의 그림을 레퍼런스로 올리지 말 것.** 검색해서 받은 도트 이미지, 게임 스크린샷, 아트북 사진 전부 금지다.
   **화풍을 맞추고 싶으면 우리 것을 올린다** — 전사는 우리가 그린 것이고 저작권이 우리에게 있다.
   올릴 그림은 이렇게 만든다:

   ```bash
   node assets/px-to-png.mjs warrior 10
   ```

   `assets/units/warrior-sheet.png` 이 나온다. 포즈 3칸이 가로로 나란한 **주문할 시트 구성 그대로**라,
   화풍뿐 아니라 "이런 식으로 세 칸을 달라"는 것까지 한 장으로 보여 준다. 이 파일 하나만 올린다.
3. **생성 도구의 상업 이용 약관을 확인할 것.** 이 프로젝트는 상업화를 전제한다.
4. **어떤 도구로 만들었는지 [`assets/README.md`](../assets/README.md) 원장에 적는다.** 기록 없는 파일은 커밋하지 않는다.

## 1. 무엇을 주문하는가

**캐릭터 한 명 = 시트 한 장.** 한 장 안에 **포즈 세 개를 가로로** 나란히 넣는다.

| 칸 | 이름 | 무엇 |
|---|---|---|
| 왼쪽 | **대기** | 평소에 서 있는 자세. 무기를 내리거나 세워 든다 |
| 가운데 | **치켜듦** | 무기를 머리 위로 들어 올린 자세. 공격 직전이자 마법 시전 중의 자세다 |
| 오른쪽 | **내리침** | 무기를 앞으로 내리친 자세. 공격이 끝나는 순간 |

세 칸을 한 장에 넣는 이유는 **세 포즈의 생김새·색·크기가 반드시 같아야** 하기 때문이다.
따로 세 번 그리게 하면 얼굴이 매번 달라진다.

## 2. 지켜야 할 규격

### 시점 — 3/4 반측면

**정면을 똑바로 보게 하지 말 것.** 몸을 **화면 오른쪽으로 비스듬히** 튼다.

- **가까운 쪽 = 화면 오른쪽.** 무기 든 팔이 여기 온다. 어깨가 크고 낮게 보인다
- **먼 쪽 = 화면 왼쪽.** 방패·보조 장비가 여기 온다. 어깨가 작고 높게 보이고, 몸통에 일부 가린다
- **얼굴 중심선(코)이 오른쪽으로 밀린다.** 오른쪽 눈은 얼굴 가장자리에 눌려 좁아지고, 왼쪽 눈은 온전한 폭이다
- **두 발을 어긋나게 딛는다.** 가까운 발이 앞, 먼 발이 뒤 (한 칸 높게)

적 팀은 화면이 좌우로 뒤집어 쓴다. 그래서 **왼쪽을 보는 그림은 주문하지 않는다.**

### 크기와 정렬

| 항목 | 값 |
|---|---|
| 최종 해상도 | **48 × 64 도트** — 이건 우리 변환기가 맞춘다 |
| 발바닥 | 아래에서 4번째 줄 (`y = 59`) |
| 좌우 중심 | `x = 24` |
| 머리 비율 | **전신의 1/3 정도.** 작으면 얼굴이 안 읽힌다 |
| 세 칸 | 키·발높이·중심이 **세 칸 모두 같아야** 한다 |

GPT 에게는 **크게 그리라고** 주문한다 (칸당 500픽셀 이상). 우리가 줄인다.

### 픽셀 규칙

| 반드시 | |
|---|---|
| 외곽선 | 실루엣 바깥을 **1도트 검정**(`#1d1d24`)으로 두른다 |
| 가장자리 | **딱 떨어지는 계단.** 흐릿한 중간색이 끼면 안 된다 |
| 명암 | 재질마다 밝은 색 + 어두운 색 **두 단계**. 왼쪽 위에서 빛이 온다 |
| 배경 | **완전 투명** (또는 순수 마젠타 `#ff00ff`) |

| 금지 | 왜 |
|---|---|
| 안티앨리어싱 · 흐림 · 그라디언트 | 도트가 아니게 된다. 줄이면 진창이 된다 |
| 그림자 효과 · 발광 · 외곽선 빛번짐 | 같은 이유 |
| 원근 · 기울어진 바닥 | 캐릭터 열셋이 한 줄에 서야 한다 |
| 글씨 · 로고 · 워터마크 | |
| 얼굴 주름, 가는 장식선, 잔무늬 | **48×64 로 줄이면 전부 사라진다.** 큰 덩어리와 강한 색 대비로 |

### 팔레트 — 이 12색만 쓴다

변환기가 어차피 이 색으로 스냅한다. 미리 맞춰 주면 결과가 훨씬 깨끗하다.

| 쓰임 | 밝음 | 중간 | 그늘 |
|---|---|---|---|
| 외곽선 | | `#1d1d24` | |
| 금속 | `#eef2f7` | `#cfd6e0` | `#8fa3b8` |
| 피부 | `#e8c39e` | | `#c08a5e` |
| **대표색** | `#b23a48` | | `#7d2632` |
| 가죽 · 천 | `#8a7550` | | `#5e4f36` |
| 바닥 그림자 | | `#c9c0ad` | |

**대표색은 캐릭터마다 다르다.** [`assets/manifest.json`](../assets/manifest.json) 의 그 캐릭터 `color` 값을 쓴다
(전사 `#b23a48`, 도적 `#5b4b8a`, 마법사 `#2f6fd6`, 프리스트 `#d4a017`, 엘프 `#3e8e5a` …).
밝은 값은 그대로, 그늘은 그 색을 어둡게 한 값을 쓴다.

## 3. 그대로 붙여 넣을 주문문

`《 》` 안만 캐릭터마다 바꾼다. **`assets/units/warrior-sheet.png` 을 함께 올린다.**

```
같은 게임에 들어갈 도트 캐릭터 스프라이트 시트를 그려 주세요.
함께 올린 이미지가 이미 만들어 둔 같은 세트의 캐릭터입니다. 이 화풍·색조·비율에 맞춰 주세요.

■ 캐릭터
《도적. 후드를 깊이 눌러써 눈 위가 그늘지고, 몸을 낮춘 가벼운 자세. 단검 한 자루.》
대표색은 《#5b4b8a (보라)》 계열입니다.

■ 시트 구성
가로로 세 칸, 한 캐릭터의 세 가지 자세. 세 칸의 키·발높이·얼굴·색이 모두 같아야 합니다.
  1칸 대기   — 《단검을 역수로 쥐고 몸을 낮춘 자세》
  2칸 치켜듦 — 《단검 든 팔을 뒤로 크게 뺀 자세》
  3칸 내리침 — 《단검을 앞으로 찌른 자세》

■ 시점
정면이 아니라 3/4 반측면입니다. 몸을 화면 오른쪽으로 비스듬히 틉니다.
무기 든 팔이 화면 오른쪽(가까운 쪽), 보조 장비가 화면 왼쪽(먼 쪽)입니다.
코가 얼굴 중심보다 오른쪽으로 밀리고, 오른쪽 눈이 가장자리에 눌려 좁아집니다.
두 발은 어긋나게 딛습니다. 가까운 발이 앞, 먼 발이 뒤입니다.

■ 그리는 방식
진짜 도트 그림입니다. 안티앨리어싱, 흐림, 그라디언트, 발광, 그림자 효과를 쓰지 마세요.
실루엣 바깥을 1도트 검정(#1d1d24)으로 두릅니다.
재질마다 밝은 색과 어두운 색 두 단계만 씁니다. 빛은 왼쪽 위에서 옵니다.
색은 12가지 이하로 씁니다.
배경은 완전히 투명합니다.
머리가 전신의 1/3 정도인 2.5~3등신입니다.
이 그림은 최종적으로 48×64 도트로 줄어듭니다.
얼굴 주름, 가는 장식선, 잔무늬는 줄이면 사라지니 넣지 마세요.
큰 덩어리와 강한 색 대비로 그려 주세요.
원근, 기울어진 바닥, 글씨, 로고는 넣지 마세요.

■ 출력
칸마다 캐릭터 키가 500픽셀 이상 되도록 크게, PNG 로 주세요.
```

## 4. 받은 뒤 우리가 하는 일

```bash
# 1. PNG 를 .px 초안으로 변환한다 (가로 3칸)
node assets/png-to-px.mjs <받은시트.png> rogue 3

# 2. assets/units/rogue.px 를 열어 눈으로 보고 손으로 다듬는다
#    - 눈·입이 뭉개졌으면 직접 찍는다
#    - 세 포즈의 키와 발높이가 어긋났으면 줄을 옮긴다
#    - 외곽선이 끊긴 곳을 k 로 이어 준다

# 3. SVG 로 굽는다
node assets/build-units.mjs

# 4. 화면에서 본다
npm run dev   # 편성 탭 → 한 판 시험 → 재생
```

변환기가 하는 일:

1. PNG 를 직접 읽는다 (외부 라이브러리 없이)
2. 가로로 등분해 포즈 칸을 나눈다
3. 칸마다 캐릭터가 차지한 범위만 잘라낸다
4. 48×64 격자로 줄인다 — 한 칸에 들어온 원본 픽셀 중 **가장 많이 나온 색**을 고른다 (최근접보다 덜 튄다)
5. 모든 색을 팔레트 12색 중 가장 가까운 색으로 스냅한다 → **안티앨리어싱이 여기서 사라진다**
6. 발바닥을 `y=59`, 좌우 중심을 `x=24` 에 맞춘다
7. `pose0` / `pose1` / `pose2` 레이어로 `.px` 를 쓴다

### 두 가지 방식이 공존한다

| | 레이어 | 누가 | 움직임 |
|---|---|---|---|
| **부위 분리** | `body` `head` `arm0/1/2` … | 손으로 그릴 때 (전사가 이 방식) | 몸통은 하나, 무기 팔만 갈아 끼운다 |
| **전신 포즈** | `pose0` `pose1` `pose2` | **이미지 생성 AI 에게 맡길 때** | 포즈마다 전신을 통째로 갈아 끼운다 |

한 파일에 둘을 섞을 수 없다. `build-units.mjs` 가 막는다.
AI 에게 부위를 나눠 그리게 하면 **칸마다 어깨 위치가 달라져** 갈아 끼울 때 팔이 순간이동한다. 그래서 전신으로 받는다.

## 5. 반려 기준 — 하나라도 걸리면 다시 주문한다

- [ ] 세 칸의 **키와 발높이**가 다르다 → 애니메이션이 튄다
- [ ] 세 칸의 **얼굴·색·복장**이 다르다 → 다른 사람처럼 보인다
- [ ] **정면을 똑바로** 보고 있다 → 납작해 보인다. 3/4 로 다시
- [ ] 가장자리가 **흐릿하다** (중간색이 껴 있다) → 줄이면 진창이 된다
- [ ] 배경이 **투명이 아니다** → 잘라내기가 안 된다
- [ ] **그림자·발광 효과**가 들어갔다
- [ ] 얼굴이 **잔주름·가는 선**으로 되어 있다 → 48×64 에서 전부 사라진다
- [ ] 색이 **12가지를 넘는다** → 스냅하면 의도한 색이 안 나온다
- [ ] 원근이 들어가 **바닥이 기울어 있다**
- [ ] 기존 캐릭터와 **한 세트로 안 보인다**
